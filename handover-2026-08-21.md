## 🔴 Start here — pre-commit and pre-push are gutted

`.husky/pre-commit` currently runs **nothing** — `lint-staged`, `check-forbidden-code.js`,
`check-project-invariants.js`, and `type-check` were all removed, not just the openapi-specific
piece. Every commit goes through with no gate at all right now.

`.husky/pre-push` still fetches a fresh `openapi.json` from the dev API and diffs it against
what's committed, but the block that failed the push on drift (`DRIFT=1 → exit 1`) was removed.
It always prints "✅ OpenAPI schema in sync." now, whether or not that's true.

**Why:** `openapi-zod-client` (the package that turns `openapi.json` into `src/generated/api.ts`)
keeps emitting Zod v3-style single-argument `z.record(valueType)` calls for `Map`-shaped fields
(e.g. `product_template_version_pins`) — invalid under the Zod v4 installed here, which requires
`z.record(keyType, valueType)`. Every `pnpm fetch:openapi` run regenerates the file and
reintroduces the same 2-3 broken calls, which fails `pnpm type-check` outright. The drift check in
pre-push was failing pushes on this generator bug, not on real backend changes, so it was disabled
to keep working. Pulling `develop` before each session's work avoided most of the pain, but this
is a workaround, not a fix.

**Recommendation from the outgoing developer:** swap `openapi-zod-client` for `typed-openapi`.
Unconfirmed whether this was already planned — flagging it here either way.

**Before restoring either hook:** fix the generator issue first (switch the package, or patch
around its `z.record()` output), otherwise pre-push will immediately start blocking every push
again on the same non-issue. Until then, treat `pnpm type-check` as manual-only after every
`pnpm fetch:openapi` — the 2-3 broken `z.record()` calls need a one-line fix each time (add the
missing `z.string()` key-schema argument) before anything else will type-check.
