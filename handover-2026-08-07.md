## 4. Live blockers you will hit

> ## 🔴 Bank Product Template creation is broken on dev — start here
>
> Publishing a Bank Product Template returns **500 `PRODUCT_TEMPLATE_CODE_GENERATION_ERROR`**
> ("Failed to generate a unique template code. Please try again."). **The message is wrong in the way
> that matters: retrying can never succeed.** This is not filed in Jira — this brief is the record.
>
> **Mechanism** (`refinext-api`, `product_templates/application/services.py:70-79`) — two defects compound:
>
> 1. **The five-attempt retry loop is a no-op.** Nothing inside it mutates state, so every pass computes
>    the identical candidate. It succeeds on attempt one or fails five times the same way.
> 2. **`count + 1` is not a sequence.** The candidate is `count_by_financing_type(...) + 1`, but
>    `template_code` is assigned once and is immutable (DB trigger), while the count is a live aggregate
>    over _versions_. The update schema permits changing a draft's `financing_type`, and seeded rows carry
>    codes the generator never produced — either desynchronises the counter from the issued codes.
>
> Once they diverge the failure is **permanent** for that tenant and financing type.
>
> **Reproduce in three public-API calls** (verified end to end against a local stack):
>
> 1. Create a `full_refinancing` template — note the code it returns, e.g. `REFI-FULL-010`
> 2. `PATCH` that draft's `financing_type` to `partial_refinancing` — the count drops, the code persists
> 3. Create another `full_refinancing` template → **500**, byte-identical to the reported response
>
> **Backend-owned — no FE change can fix it.** The fix is to derive the suffix from the maximum issued
> suffix for that prefix, or use a real sequence with a unique-constraint retry, rather than a row count.
> The FE half is already done: the `errors.` key for this code shipped in MR !200, so once dev picks it up
> the failure reads as itself instead of a generic toast. That changes the wording, not the outcome.
>
> **To find which tenants and types are already bricked**, run against the database: for each financing
> type, compare `count(distinct templates having a version of that type) + 1` against the existing
> `template_code` suffixes for that prefix — any collision is a permanently blocked combination.

## 6. Conventions that bite

> **`CLAUDE.md` and `.claude/rules/` are the contract, and they win over anything written here.** This
> section is not a second rulebook — it is the shortlist of what most often catches someone new, with a
> pointer to the real source. If this list and `CLAUDE.md` ever disagree, `CLAUDE.md` is right and this
> list is stale.

Most of these are enforced by git hooks, so you will meet them whether you read this or not:

- **Every commit needs a Jira ticket or `#no-ticket`** — `commitlint` rejects the commit otherwise.
- **No AI attribution in commits.** Hard rule.
- **Stage files explicitly.** No `git add -A` / `git add .`.
- **`pre-push` checks `openapi.json` against the dev API** and fails on drift. If it fires, run
  `pnpm fetch:openapi` and re-verify your contract assumptions — do not force past it.
- **API data is Zod-parsed in the `queryFn`.** Never `response.data as SomeType`.
- **No `useEffect` for fetching; no `useMemo`/`useCallback`/`React.memo`** — React Compiler is enabled.
- **Every mutation needs `onError`; every foreground query needs an `isError` branch.** Use the dynamic
  `errors.<CODE>` lookup with a generic fallback — never a `switch` per code.
- **i18n keys go into `en` _and_ `de`.** The invariant script checks parity — but a key missing from
  **both** locales passes every gate and ships visibly broken. Check the page in a browser.
- **shadcn/ui first.** Raw HTML in a shadcn slot needs an inline `NOTE:` comment justifying it.
- **An `errors.<CODE>` key must match the wire _value_, which is not always the Python constant name.**
  `PRODUCT_TEMPLATE_IMMUTABILITY_VIOLATION = "IMMUTABILITY_VIOLATION"` is the clearest case — the FE key is
  deliberately **un**prefixed. Read the right-hand side of the assignment in
  `../refinext-api/src/app/shared/errors/codes.py`. Getting this wrong is silent: the key never matches and
  the toast falls back to `errors.generic`. It had already shipped wrong twice.

Before committing: `pnpm test:run` · `pnpm type-check` · `pnpm lint`, then
`git add <files> && node scripts/check-project-invariants.js` (it reads the staged diff).

## 7. Decisions in motion — do not undo

Deliberate choices that look like bugs. Changing any of these without asking will cost rework:

- **LEI validation mirrors the backend's wrong algorithm on purpose** (Q-065). Parity is intentional
  until both sides are fixed together.
- **The FA Pricing section is only half-removed.** The VFE half was implemented and then deliberately
  reverted so the whole section can go in one pass once the backend lands. It is parked, not forgotten
  (Q-035) — `effective_rate` is required on create, `NOT NULL` in the DB, and is what Epic 3 Financing
  reads, so removal is sequencing-blocked on Epic 3 existing at all.
- **FA versioning was built, then removed on an explicit decision** — the client withdrew CR-FA-04 on
  6/8. The FE surfaces are gone; **the backend endpoints are still live** (Q-072). Do not "restore" the
  version history from git history, and do not build against those endpoints.
- **Epic 15 has a design file, but most of what it shows is cut scope** — four-eyes, deprecate/archive,
  migration wizard, effective-task preview. **Do not build from those frames.**
- **Where a CR and its epic disagree, the CR wins.** The epic is the original ambition; the CR is
  committed scope. Not a judgement call — it is a standing rule (`documentation-templates.md` §1).
- **Framework Agreement _edit_ steps deliberately do not floor start dates at today** — existing
  agreements legitimately have past start dates. See `.claude/rules/date-inputs.md` §8.
