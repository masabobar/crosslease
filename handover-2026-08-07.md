### 2.1 Product-template error codes — fixed, staged, not yet committed

⚠️ **This work is in the working tree and staged, not committed or merged.** `git status` shows both
locale files staged; commit them before anything else.

Three codes the API emits had no i18n key in either locale, so they rendered as raw
`SCREAMING_SNAKE_CASE`. Added to `en/` and `de/productTemplates.json`, wording taken from each raise site
in `../refinext-api/` rather than from the code name:

| Code                                | Fires when                                                            |
| ----------------------------------- | --------------------------------------------------------------------- |
| `PRODUCT_TEMPLATE_NOT_ACTIVATABLE`  | `submit_for_activation` is called on a version that is not a draft    |
| `PRODUCT_TEMPLATE_NOT_DEPRECIABLE`  | `submit_deprecation` is called on a version that is not published     |
| `PRODUCT_TEMPLATE_VALIDITY_EXPIRED` | binding to a template whose active version's `valid_until` has passed |

**Verifying those turned up three more defects, all now fixed.** Checking every product-template code by
**wire value** rather than by constant name showed two shipped keys could never match:

```
PRODUCT_TEMPLATE_REFERENCE_CHECK_FAILED  →  REFERENCE_CHECK_FAILED
PRODUCT_TEMPLATE_DRAFT_EXISTS            →  DRAFT_VERSION_ALREADY_EXISTS
```

`codes.py` declares those constants with **different string values**. Display goes through
`t("errors." + err.code)` and `err.code` carries the _value_, so both keys were dead and fell through to
`errors.generic` — a user hitting "a draft already exists" saw "Something went wrong" instead of the
reason. A third code, `TEMPLATE_NOT_PUBLISHED`, had no key at all. All three corrected.

Coverage is now complete and was checked programmatically, not by eye: every product-template wire value
has a key in both locales, and no dead keys remain. `type-check`, `lint`, 1595 tests and
`check-project-invariants.js` all pass.

> **The trap worth carrying forward:** a key must match the **wire value**, which is not always the Python
> constant name. `PRODUCT_TEMPLATE_IMMUTABILITY_VIOLATION = "IMMUTABILITY_VIOLATION"` is the clearest case
> — the FE key is deliberately **un**prefixed and must not be "corrected". When adding an `errors.<CODE>`
> key, read the right-hand side of the assignment in `../refinext-api/src/app/shared/errors/codes.py`,
> never the constant name.

**Not browser-verified** — the affected screens are role-gated and no login was available. The change is
i18n-only with no code path touched, but per `browser-verification.md` that is a claim, not a check.

## 5. The context that is not in git

> ⚠️ **`.project-management/` is gitignored** (`.gitignore:34`). Cloning this repo does **not** give you:
>
> | File                           | What it holds                                                                     |
> | ------------------------------ | --------------------------------------------------------------------------------- |
> | `output/progress/DASHBOARD.md` | The decision journal — _why_ things were built the way they were, in prose, dated |
> | `input/open-questions.md`      | The blocker register — every open BE/design gap, by priority                      |
> | `rules/project-rules.md`       | Domain rules, role wire values, API conventions                                   |
>
> These are per-developer and cannot be shared through git.

§4 above is a distilled extract of the register — the part that blocks active work. It is **not** the whole
thing, and the register is the source of truth for blockers.

**To get the full context, pick one:**

1. Ask the outgoing developer to send the directory directly — it is three files that matter
2. Pull a ticket's own text from Jira with `/jira-sync PRD1042-XXXX`
3. Read the backend at `../refinext-api/` — authoritative for every `api-contract` blocker in §4

Option 1 is strongly preferred. Options 2 and 3 recover the facts but not the decision history.

> One trap worth naming: **`project-rules.md` outranks `CLAUDE.md`** in this repo's precedence ladder, so a
> stale line there silently overrides a correct one elsewhere — and because the file is unshared, nobody
> else can see or fix it. One such line documented an `Authorization: Bearer` auth model months after the
> app moved to cookie-borne JWTs. If something in the code contradicts `CLAUDE.md`, check that file before
> assuming the code is wrong.

## 6. Conventions that bite

> **`CLAUDE.md` and `.claude/rules/` are the contract, and they win over anything written here.** This
> section is not a second rulebook — it is the shortlist of what most often catches someone new, with a
> pointer to the real source. If this list and `CLAUDE.md` ever disagree, `CLAUDE.md` is right and this
> list is stale.

Most of these are enforced by git hooks, so you will meet them whether you read this or not:

- **Every commit needs a Jira ticket or `#no-ticket`** — `commitlint` rejects the commit otherwise.
- **No AI attribution in commits.** Hard rule.
- **Stage files explicitly.** No `git add -A` / `git add .`.
- **`pre-push` checks `openapi.json` against the dev API** and fails on drift. If it fires, run
  `pnpm fetch:openapi` and re-verify your contract assumptions — do not force past it.
- **API data is Zod-parsed in the `queryFn`.** Never `response.data as SomeType`.
- **No `useEffect` for fetching; no `useMemo`/`useCallback`/`React.memo`** — React Compiler is enabled.
- **Every mutation needs `onError`; every foreground query needs an `isError` branch.** Use the dynamic
  `errors.<CODE>` lookup with a generic fallback — never a `switch` per code.
- **i18n keys go into `en` _and_ `de`.** The invariant script checks parity — but a key missing from
  **both** locales passes every gate and ships visibly broken. Check the page in a browser.
- **shadcn/ui first.** Raw HTML in a shadcn slot needs an inline `NOTE:` comment justifying it.

Before committing: `pnpm test:run` · `pnpm type-check` · `pnpm lint`, then
`git add <files> && node scripts/check-project-invariants.js` (it reads the staged diff).

## 7. Decisions in motion — do not undo

Deliberate choices that look like bugs. Changing any of these without asking will cost rework:

- **LEI validation mirrors the backend's wrong algorithm on purpose** (Q-065). Parity is intentional
  until both sides are fixed together.
- **The FA Pricing section is only half-removed.** The VFE half was implemented and then deliberately
  reverted so the whole section can go in one pass once the backend lands. It is parked, not forgotten
  (Q-035) — `effective_rate` is required on create, `NOT NULL` in the DB, and is what Epic 3 Financing
  reads, so removal is sequencing-blocked on Epic 3 existing at all.
- **FA versioning was built, then removed on an explicit decision** — the client withdrew CR-FA-04 on
  6/8. The FE surfaces are gone; **the backend endpoints are still live** (Q-072). Do not "restore" the
  version history from git history, and do not build against those endpoints.
- **Epic 15 has a design file, but most of what it shows is cut scope** — four-eyes, deprecate/archive,
  migration wizard, effective-task preview. **Do not build from those frames.**
- **Where a CR and its epic disagree, the CR wins.** The epic is the original ambition; the CR is
  committed scope. Not a judgement call — it is a standing rule (`documentation-templates.md` §1).
- **Framework Agreement _edit_ steps deliberately do not floor start dates at today** — existing
  agreements legitimately have past start dates. See `.claude/rules/date-inputs.md` §8.
